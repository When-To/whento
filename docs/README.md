# WhenTo documentation

Two audiences. The [root README](../README.md) covers what WhenTo is, how to
configure it, and the API; the pages here cover what is too long to keep there —
the procedures an **operator** needs, and the design a **contributor** needs.

## For contributors

| Document                             | What it answers                                                                                                            |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| [architecture.md](architecture.md)   | How the system is put together: the domain split, `pkg/`, the single binary, and a request followed end to end.             |
| [adr/](adr/README.md)                | Why the load-bearing decisions are what they are — build tags, capability-based participant links, no ORM, no telemetry.    |
| [development.md](development.md)     | From a fresh clone to a pull request that passes CI: setup, the conventions, and what to run before pushing.                |

Start with `development.md` if you want to build it, `architecture.md` if you
want to change it, and the ADRs before proposing anything that contradicts one.

## For operators

| Document                                              | What it answers                                                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| [backup-restore.md](backup-restore.md)                | How to back up Postgres and the JWT keys, how to restore them, how long to keep backups, and how to prove a backup works. |
| [migration-rollback.md](migration-rollback.md)        | Migrations run automatically at every container start. What to do when one of them is the problem.                  |
| [upgrade-postgres-redis.md](upgrade-postgres-redis.md) | Why a Postgres major upgrade needs a dump and a restore, and the step-by-step procedure for both Postgres and Redis. |
| [reverse-proxy.md](reverse-proxy.md)                  | Caddy and nginx examples, and — the part that is easy to get wrong — how to set `TRUSTED_PROXIES` to match.          |
| [logging-and-privacy.md](logging-and-privacy.md)      | What WhenTo writes to its logs, what it deliberately does not, what lands in Redis and in what form, and for how long. |
| [hardening-docker.md](hardening-docker.md)            | What `docker-compose.yml` hardens, what it deliberately leaves off, and how to go further.                          |

`swagger/` is generated by `make swagger` from the `// @…` annotations in the
handlers. It is git-ignored and must not be edited by hand.

The release history is in [CHANGELOG.md](../CHANGELOG.md); how a release is cut
is in [CONTRIBUTING](../.github/CONTRIBUTING.md#release-process).

## Reading order for a new deployment

1. [root README → Deployment](../README.md#-deployment) — get the stack up.
2. [reverse-proxy.md](reverse-proxy.md) — TLS, and `TRUSTED_PROXIES` so that rate
   limiting counts real clients instead of the proxy.
3. [backup-restore.md](backup-restore.md) — before the instance holds anything you
   would miss.
4. [hardening-docker.md](hardening-docker.md) and
   [logging-and-privacy.md](logging-and-privacy.md) — before it holds anyone else's data.
